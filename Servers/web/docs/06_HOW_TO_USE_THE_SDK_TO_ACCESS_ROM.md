# PlusOS: How to Use the SDK to Access the ROM

> **Operating System:** PlusOS  
> **Source SDK Directories:** `C:\Users\Evil\PlusOS\sdks\macplus\` and `C:\Users\Evil\PlusOS\sdks\macse\`  
> **Target Toolchain:** `m68k-elf-gcc` / `m68k-linux-gnu-gcc` (WSL Ubuntu)  

---

## 1. SDK Architecture & Directory Layout

PlusOS provides two standalone, fully self-contained SDKs generated directly from the bit-identical assembly source tree of the Macintosh ROMs (upstream repository: **[https://github.com/jonathanschilling/mac_rom](https://github.com/jonathanschilling/mac_rom)**):

1. **`sdks/macplus/` (Macintosh Plus SDK)**:
   - Primary SDK for software running on both the Macintosh Plus and the Macintosh SE.
   - Provides `<plusrom/...>` headers covering all 626 traps implemented in the 128 KB Mac Plus ROM ($0075).
2. **`sdks/macse/` (Macintosh SE SDK)**:
   - Specialized SDK for Macintosh SE and SE FDHD hardware.
   - Provides `<serom/...>` headers adding SE-only features (Apple Desktop Bus `ADB.h`, `KeyTranslate`, extended SCSI calls).

> [!NOTE]
> **Open & Standalone Generation**: Both SDKs are generated by `tools/sdkgen/` which assembles the ROMs from the open assembly source tree at `https://github.com/jonathanschilling/mac_rom`. The build pipeline runs portably using standard GNU cross-compilers (`m68k-elf-gcc` or `m68k-linux-gnu-gcc`) without relying on proprietary compilers or external SD cards.

```
sdks/macplus/ (and sdks/macse/)
  ├── include/
  │     ├── libc/               # Standard C library headers (stdio.h, stdlib.h, string.h, math.h)
  │     ├── plusos/             # PlusOS API headers (plusos.h, api.h, gfx.h, theme.h)
  │     ├── plusnet/            # DaynaPORT SCSI TCP/IP stack (net.h, dayna.h)
  │     ├── plus3d/             # Fixed-point 3D engine (plus3d.h)
  │     └── plusrom/            # ROM Manager headers (QuickDraw.h, MemoryMgr.h, FileMgr.h, ...)
  ├── build/lib/
  │     ├── crt0_app.o          # C runtime startup & self-relocation stub
  │     ├── libc.a              # Embedded C standard library
  │     ├── libplusos.a         # PlusOS syscall stubs and client helpers
  │     ├── libplusrom.a        # ROM glue stubs (or libserom.a for SE)
  │     ├── libplusgfx.a        # PlusGFX 2D rendering and Bayer dithering
  │     ├── libplusnet.a        # TCP/IP network protocol stack
  │     └── librt_app.a         # Application runtime support
  ├── ld/
  │     └── app.ld              # Linker script for relocatable .pex binaries
  └── sdk.mk                    # Master Makefile include for application builds
```

## 2. How the SDK Accesses the ROM from C & C++

Classic Macintosh ROM traps do not use standard C cdecl calling conventions. The PlusOS SDK uses GCC's Motorola 68000 inline opcode extension to generate native A-line traps with zero overhead:

### Inline Trap Injection (`M68K_INLINE`)
In `include/plusrom/MacPrelude.h`:
```c
#define M68K_INLINE(...) = { __VA_ARGS__ }
```

When a function is declared with `= { 0xAxxx }`, GCC emits the raw 16-bit trap word directly in the compiled instruction stream:

```c
/* Toolbox Trap: Pascal stack calling convention */
pascal void FrameRect(const Rect *r) M68K_INLINE(0xA8A1);

/* OS Trap: Register-based calling convention using GCC register binding */
#pragma parameter __A0 NewPtr(__D0)
pascal Ptr NewPtr(Size size) M68K_INLINE(0xA11E);
```

### Compiler Register Binding (`#pragma parameter`)
For OS traps where arguments must reside in specific 68000 registers:
* `#pragma parameter __A0 NewPtr(__D0)` instructs the compiler:
  1. Place the `size` parameter into data register `D0`.
  2. Execute opcode `$A11E` (the `_NewPtr` trap).
  3. Retrieve the returned pointer from address register `A0`.

No assembly glue or subroutine call is needed—the compiler generates optimal 68000 machine code directly at the call site!

## 3. ROM Manager Catalog in the SDK

The SDK divides the ROM into modular header files corresponding to the classic Macintosh system managers:

| Header File | Subsystem | Key ROM Traps Exposed |
|:---|:---|:---|
| `<plusrom/QuickDraw.h>` | QuickDraw 2D Graphics | `InitGraf`, `OpenPort`, `LineTo`, `MoveTo`, `FrameRect`, `PaintOval`, `CopyBits`, `ClipRect` |
| `<plusrom/MemoryMgr.h>` | Memory Management | `NewPtr`, `DisposPtr`, `NewHandle`, `DisposHandle`, `HLock`, `HUnlock`, `CompactMem` |
| `<plusrom/FileMgr.h>` | File System (HFS) | `FSOpen`, `FSRead`, `FSWrite`, `FSClose`, `Create`, `SetFInfo`, `PBGetCatInfoSync` |
| `<plusrom/EventMgr.h>` | OS Event Queue | `PostEvent`, `GetNextEvent`, `WaitNextEvent`, `FlushEvents` |
| `<plusrom/WindowMgr.h>` | Window Management | `NewWindow`, `GetNewWindow`, `SelectWindow`, `DragWindow`, `ShowWindow` |
| `<plusrom/MenuMgr.h>` | Menu Bar & Menus | `InitMenus`, `NewMenu`, `AppendMenu`, `MenuSelect`, `DrawMenuBar` |
| `<plusrom/DialogMgr.h>` | Dialogs & Alerts | `GetNewDialog`, `ModalDialog`, `Alert`, `GetDialogItem`, `SetDialogItem` |

## 4. Application Build Flags & `sdk.mk`

When compiling applications with the SDK, specific GCC flags are required to comply with Macintosh hardware and PlusOS architecture:

```makefile
# Extracted from sdks/macplus/sdk.mk:
CC      = m68k-elf-gcc
CFLAGS  = -m68000                 # Target base 68000 CPU (no 68020 instructions)
CFLAGS += -ffixed-a5              # Reserve A5 register for Macintosh A5 World & QuickDraw
CFLAGS += -fno-builtin            # Do not substitute GCC built-in library functions
CFLAGS += -fPIE                   # Generate Position-Independent Code
CFLAGS += -nostdlib               # Do not link host C library
CFLAGS += -I$(SDK_DIR)/include    # Include SDK header root
CFLAGS += -I$(SDK_DIR)/include/plusos
CFLAGS += -I$(SDK_DIR)/include/plusrom
```

### The `-ffixed-a5` Requirement
The 68000 register `A5` is fundamentally reserved by the Macintosh architecture:
* `0(A5)` holds the pointer to the current QuickDraw `GrafPort` (`thePort`).
* Negative offsets `(A5 - N)` hold QuickDraw global variables (`white`, `black`, `gray`, `arrow`, `screenBits`).
* Positive offsets `(A5 + N)` hold the application Jump Table.
Specifying `-ffixed-a5` prevents GCC from using `A5` as a general scratch register.

## 5. Complete Code Example: C Application Using PlusOS & ROM

This complete, compilable example creates a native PlusOS application that uses the PlusOS console and invokes ROM QuickDraw to draw shapes on screen:

```c
#include <plusos/plusos.h>
#include <plusrom/QuickDraw.h>
#include <stdio.h>

int main(int argc, char **argv)
{
    printf("Initializing QuickDraw from PlusOS application...\n");

    /* Verify QuickDraw is available */
    if (!plusos_has(PLUSOS_HAVE_QD)) {
        printf("QuickDraw not initialized by kernel!\n");
        return -1;
    }

    /* Access QuickDraw globals via A5 */
    QDGlobals *qd = (QDGlobals *)plusos->qd;

    /* Define drawing rectangle */
    Rect r;
    SetRect(&r, 50, 50, 250, 200);

    /* Invoke ROM QuickDraw traps directly */
    EraseRect(&r);                          /* Trap $A8A3 */
    FrameRect(&r);                          /* Trap $A8A1 */
    
    /* Draw diagonal line */
    MoveTo(50, 50);                         /* Trap $A893 */
    LineTo(250, 200);                       /* Trap $A891 */

    /* Draw nested rounded rectangle */
    Rect inner;
    SetRect(&inner, 80, 80, 220, 170);
    FrameRoundRect(&inner, 16, 16);         /* Trap $A8B0 */

    printf("Drawing complete. Press any key to return to shell.\n");
    plusos->key_get();

    return 0;
}
```

## 6. Complete Code Example: C++ Application Using ROM

PlusOS fully supports C++ applications (including classes, constructors, and templates) via `libc.a` and `librt_app.a`:

```cpp
#include <plusos/plusos.h>
#include <plusrom/QuickDraw.h>

class CanvasBox {
private:
    Rect bounds;
public:
    CanvasBox(int l, int t, int r, int b) {
        SetRect(&bounds, l, t, r, b);
    }

    void draw(int oval) {
        if (oval) {
            PaintOval(&bounds);             /* Trap $A8B7 */
        } else {
            PaintRect(&bounds);             /* Trap $A8A2 */
        }
    }
};

int main(int argc, char **argv)
{
    CanvasBox box1(100, 100, 200, 200);
    CanvasBox box2(220, 100, 320, 200);

    box1.draw(0);   /* Draw filled rectangle */
    box2.draw(1);   /* Draw filled oval */

    plusos->sleep_ticks(120);   /* Wait 2 seconds */
    return 0;
}
```
